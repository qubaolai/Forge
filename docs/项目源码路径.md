# Forge 项目学习路径

## 1. 目标与范围

这份学习路径面向当前仓库代码（`/Users/almond/Documents/git_repostory/Forge`），目标是：

1. 先跑通系统，再理解主链路，再能独立改动并验证。
2. 覆盖后端 `chat` 路径与 `adaptive run` 路径，以及前端流式交互关键点。
3. 每天都有可执行任务、可提交产物、可验证标准。

## 2. 当前代码基线（先统一认知）

以下是以当前仓库为准的事实，和历史设计文档可能有差异：

1. 对话与任务是两条入口：
   - 聊天：`POST /api/v1/chat/completions`
   - 任务：`POST /api/v1/runs`
2. 当前未看到 `ChatCompletionIn.mode` 三路路由形态；`chat` 与 `runs` 已拆分。
3. 仓库当前没有顶层 `cli/` 目录（与部分旧文档描述不一致）。
4. `server/README.md` 当前为空，以 `server/Makefile` 与代码为准。

## 3. 学习前准备（第 0 天，30-60 分钟）

### 3.1 环境准备

在 `server/` 目录执行：

```bash
make install-dev
make env-setup
```

在 `web/` 目录执行：

```bash
npm install
```

### 3.2 最小可运行验证

1. 启动后端：`cd server && APP_ENV=dev make dev`
2. 启动前端：`cd web && npm run dev`
3. 打开前端页面，确认可以进入登录页与聊天页。

### 3.3 产物

1. 一份你自己的运行记录（文本即可）：启动命令、端口、是否成功。
2. 一张系统结构草图：`web -> api -> chat/adaptive`。

## 5. 每日固定动作模板（建议）

每天按这个节奏执行：

1. `20%` 时间读代码：只追一条主链路，不并行发散。
2. `60%` 时间动手：运行、打断点、改小实验、看事件/落盘。
3. `20%` 时间产出：写笔记、总结边界、列遗留问题。

每日结束前必须回答 3 个问题：

1. 今天新增了哪条“可复述的机制理解”？
2. 今天验证了哪条“设计红线确实被代码执行”？
3. 今天留下了哪些“明天要验证的假设”？

完成 10 天后，你应达到以下标准：

1. 能独立新增一个 `adaptive` 校验规则，并补齐单测。
2. 能独立定位一次 run 卡在 `BLOCKED/FAILED` 的根因。

如果未达到，请回到 Day 5-8 重做一遍，以“补测试 + 跑通失败分支”为主。
